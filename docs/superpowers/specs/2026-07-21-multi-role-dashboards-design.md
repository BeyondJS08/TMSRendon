# Multi-Role Dashboard Previews (ERP / IMS / TMS) — Design

**Date:** 2026-07-21
**Status:** Approved by user
**Scope:** `frontend-tms` only. Presentational preview of 9 dashboard variants (3 systems × 3 roles) with real routing. No backend calls, no auth, no CRUD.

## Context

TMSRendon combines three systems for TransRendon (Mexican terrestrial logistics):

- **TMS** — Transportation Management System: trips, fleet, drivers, GPS telematics (Samsara/Geotab), Carta Porte.
- **ERP** — Enterprise Resource Planning: HR, payroll (IMSS), accounting (CONTPAQi), CFDI invoicing (Facturama PAC).
- **IMS** — Inventory Management System: parts inventory, maintenance alerts, purchase orders, suppliers.

The frontend currently has `/login`, `/signup` (presentational) and a single stock shadcn `/dashboard`. This feature replaces the single dashboard with 9 preview variants so stakeholders can see how the final product will look per system and per role.

## Decisions (from brainstorming with user)

1. **Navigation model:** real routes per variant + a "Ver como" role switcher in the sidebar. Chosen over a selector landing page or a client-only switcher.
2. **Role differentiation:** distinct content per role within each system (nav items, KPIs, chart, table), not just a role badge.

## Routing

```
app/dashboard/
├── layout.tsx                 # shared chrome (SidebarProvider + AppSidebar + SiteHeader + content wrapper)
├── page.tsx                   # redirects to /dashboard/tms/superadmin
└── [system]/
    └── [role]/
        └── page.tsx           # renders variant from config
```

| System | Superadmin | Admin | User |
|---|---|---|---|
| TMS | `/dashboard/tms/superadmin` | `/dashboard/tms/admin` | `/dashboard/tms/user` |
| ERP | `/dashboard/erp/superadmin` | `/dashboard/erp/admin` | `/dashboard/erp/user` |
| IMS | `/dashboard/ims/superadmin` | `/dashboard/ims/admin` | `/dashboard/ims/user` |

- `generateStaticParams` pre-renders the 9 valid combos at build time.
- Invalid system/role → `notFound()` (404).
- `/dashboard` redirects to the default preview `/dashboard/tms/superadmin`.

## Architecture

Approach A (approved): one dynamic route + config-driven content. No 9× boilerplate.

### `lib/dashboard-config.ts` (new)

Single source of truth for all variants:

```ts
type SystemKey = 'tms' | 'erp' | 'ims'
type RoleKey = 'superadmin' | 'admin' | 'user'

interface DashboardVariant {
  system: SystemKey
  role: RoleKey
  title: string                  // e.g. "TMS · Superadministrador"
  navMain: NavItemDef[]          // sidebar modules (title, url "#", lucide icon)
  kpis: KpiCard[]                // 4 stat cards
  chart: ChartDef                // area chart: title, description, 2 series, 90-day mock data
  table: TableDef                // title, columns, rows (Record<string,string>[])
}
```

Helpers: `getDashboardVariant(system, role)`, `isSystemKey`, `isRoleKey`, `allVariantParams()` (for `generateStaticParams`), `defaultVariant`. Chart series are generated by a deterministic seeded generator (90 days ending at a fixed reference date) so builds are reproducible.

### Components

- **`app/dashboard/layout.tsx`** — chrome extracted from the old `dashboard/page.tsx` (SidebarProvider with the same `--sidebar-width`/`--header-height` custom properties, `AppSidebar variant="inset"`, `SidebarInset`, `SiteHeader`, and the `@container/main` content wrapper).
- **`components/app-sidebar.tsx`** (rework) — already a client component; resolves the current variant from `usePathname()` (layouts do not receive params of dynamic segments below them, so prop-drilling from a server layout is not possible). Nav items come from the variant config. Renders the new `RoleSwitcher` in the header area. Fixes the broken logo src `/TR.webp55` → `/TR.webp`. Drops the stock `NavDocuments` section (file left in place, unused).
- **`components/role-switcher.tsx`** (new, client) — sidebar dropdown (team-switcher pattern) showing current system + role; grouped menu: 3 systems × 3 roles; navigates with `useRouter().push('/dashboard/<system>/<role>')`.
- **`components/site-header.tsx`** (rework, client) — shows variant title (e.g. "TMS · Superadministrador") and role badge, resolved from `usePathname()`.
- **`components/section-cards.tsx`** (generalized) — accepts `cards: KpiCard[]` prop; keeps the existing card visuals (gradient, trend Badge, footer lines).
- **`components/chart-area-interactive.tsx`** (generalized) — accepts `title`, `description`, `data`, and series labels; keeps the 90/30/7-day range ToggleGroup/Select and es-MX date formatting.
- **`components/preview-table.tsx`** (new) — lightweight table built on `components/ui/table` + `Badge` for status columns. *Deviation from the originally approved design (which said "generalize data-table"): the stock `data-table.tsx` (~500 lines, dnd-kit sortable rows, drawer detail, zod schema) is tightly coupled to its demo document schema; generalizing it is high-effort/high-risk for preview-only purposes and would violate the minimal-intrusion rule in AGENTS.md. `data-table.tsx` stays untouched but becomes unused.*
- **`app/dashboard/data.json`** — deleted (superseded by typed mock data in the config).

### Content per system × role (Spanish UI)

**TMS** — modules: Viajes, Flota/Unidades, Conductores, GPS y Telemática, Carta Porte
- *Superadmin:* org-wide KPIs (viajes activos, unidades en ruta, ingresos del mes, cumplimiento), nav + Usuarios y roles / Auditoría / Configuración; chart: viajes por día (completados vs cancelados); table: flota.
- *Admin:* operational KPIs (viajes hoy, en tránsito, entregas, incidencias); chart: embarques (programados vs completados); table: viajes activos.
- *User:* personal KPIs (mis viajes, entregas hoy, km semana, incidencias); reduced nav (Mis viajes, Entregas, Documentos, Incidencias); chart: mis viajes; table: mis viajes.

**ERP** — modules: Empleados/RH, Nómina, Facturación CFDI, Contabilidad, Proveedores
- *Superadmin:* financial KPIs (nómina mensual, facturado, por cobrar, empleados); nav + Usuarios y permisos / Configuración fiscal / Auditoría; chart: ingresos vs gastos; table: facturas recientes.
- *Admin:* KPIs (por timbrar, nómina quincenal, vencidas, gastos); chart: facturación (timbradas vs pendientes); table: facturas CFDI con estatus SAT.
- *User:* personal KPIs (mis recibos, vacaciones, solicitudes, próximo pago); reduced nav (Mis recibos, Solicitudes, Mis datos); chart: mis percepciones; table: mis recibos de nómina.

**IMS** — modules: Inventario/Refacciones, Mantenimiento, Órdenes de compra, Proveedores, Taller
- *Superadmin:* global KPIs (valor inventario, SKUs, stock bajo, órdenes abiertas); nav + Usuarios / Alertas y umbrales / Auditoría; chart: movimientos (entradas vs salidas); table: refacciones con stock bajo.
- *Admin:* KPIs (entradas, salidas, OC pendientes, mantenimientos); chart: entradas vs salidas; table: órdenes de compra.
- *User:* personal KPIs (mis solicitudes, OT asignadas, consultas, avisos); reduced nav (Existencias, Mis solicitudes, Órdenes de trabajo, Avisos); chart: mis movimientos; table: mis solicitudes.

## Out of scope

- No Supabase/auth/middleware/role enforcement — all 9 routes are public previews (the approved auth spec `2026-06-23-tmsrendon-supabase-auth-foundation-design.md` layers enforcement on later).
- No module sub-pages — sidebar nav items point to `#`.
- No changes to `/login`, `/signup`, `/`.
- No backend changes.
